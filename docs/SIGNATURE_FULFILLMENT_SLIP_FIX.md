# Signature, order type and prepaid-tip slips

The previous signature fix did not cover a refresh changing the same order's tip/total snapshot. That restarted its signature request, including while saving. The signature effect now follows order identity alone and snapshots the approved checkout inputs when it starts. The display link retains request ownership after receiving the answer until the signature step explicitly finishes; background ticket/payment publications cannot replace the pad during a save. The expanded browser regression failed before this change and passes afterward. A separate link regression reproduced and verifies the publication race.

Opening an existing order now offers **Pickup / delivery** in its editor and in Today's Orders details. The server changes the existing order under a row lock, validates delivery contact/address/area/minimums and restricted specials/discounts, updates kitchen data, and records an event. Uncollected driver assignments are released when switching to pickup; picked-up, delivered or cashed-out deliveries cannot be silently reassigned. Retries use the same idempotency key. Completed/cancelled orders and pending payments cannot change type.

The delivery fee is added or removed, including for paid orders. An increase leaves only the additional balance to collect through Payments. A fee already captured on a card must first be refunded through the existing manager-authorized refund page, prefilled with the delivery fee and reason; the server refuses to reduce the total until the completed refund is in the ledger. Cash returned to the customer can be confirmed and recorded on an authorized open drawer atomically with the conversion, once. An uncaptured card authorization must first be voided through its existing payment controls and the corrected total collected. No charge, refund or cash payout is invented to make a badge or total appear correct. Net paid amounts subtract completed refunds; captured receipts remain unchanged. The editor receives saved fee/tip snapshots so its displayed total keeps a pre-existing phone tip.

The common slip formatter no longer emits **Extra tip**, a blank tip/total line, or **ADD TIP BELOW** when a tip is already on the order. It prints the recorded tip, final total and signature line instead. This applies to phone, counter and online tips, original prints, queued slip jobs and reprints because they share the formatter. Orders without an existing tip retain their tip/total blanks.

Validation: 1,015 tests passed (4 skipped), including 12 full-migration PostgreSQL fulfillment tests; seven targeted browser tests passed; lint, TypeScript and the production build passed. Browser tests use actual React components and synthetic transports. Physical Elo/Fire-tablet and printer operation are not certified by these checks.

These are shared hosted-code changes, compatible with the existing installed APK as well as 1.5.2 and future native releases. Registers and customer displays already running an earlier document must load the new hosted build when idle. No replacement APK, app-data clearing or storage reset is required for these code fixes.
